# Вебкерування записами дзвінків

Навчальний застосунок кол-центру реалізує MVC-вебінтерфейс для перегляду, додавання, виправлення й видалення записів дзвінків. Модель застосовує серверні правила і зберігає дані через SQLite. Javalin зосереджено в одному інфраструктурному адаптері.

Застосунок використовує Maven, JDK 21, Google Guice 7, Javalin 6, Jackson і SQLite; зовнішній сервер бази даних не потрібен.

## Передумови

Потрібні JDK 21 і Maven 3.9 або новіший у `PATH`. Виконуйте команди з кореня репозиторію в PowerShell.

## Зібрати та запустити

```powershell
mvn test
mvn package
mvn exec:java -Dexec.mainClass=callcenter.Main
```

Застосунок запускає локальний сервер на порту `8080`. Відкрийте `http://localhost:8080/`.
База даних зберігається у `target/callcenter.db`; тестові записи не створюються автоматично.

## Вебінтерфейс

Сторінка містить адаптивну таблицю записів, одну форму створення й редагування, підтвердження видалення та окремі повідомлення успіху й відмови. Стиль — темний.

## HTTP-маршрути

| Метод | Маршрут | Успішний статус |
|---|---|---|
| `GET` | `/api/CallCenter` | `200` |
| `POST` | `/api/CallCenter` | `201` |
| `PUT` | `/api/CallCenter/{id}` | `200` |
| `DELETE` | `/api/CallCenter/{id}` | `200` |

Відмови повертають українське JSON-повідомлення зі статусами `400`, `404`, `409` або `500`.
Новий запис має непорожній `recordingId`, невід'ємний `duration` і заданий ISO-8601 `createdAt`.

## Архітектура MVC

- **Модель:** `Call`, `CallRecording` та інтерфейс `RecordingStore` — зберігають дані в SQLite через інфраструктурний сервіс і перевіряють правила предметної області без залежності від вебфреймворку й HTTP-кодів.
- **Контролер:** `CallCenterController` — приймає дані запиту від вебсервера, викликає методи моделі й передає результат вигляду.
- **Вигляд:** `CallCenterWebView` (перетворює результат моделі на HTTP-код і дані відповіді) та клієнтська вебсторінка `src/main/resources/public/` (`index.html`, `script.js`, `style.css`).

## Правила перевірки даних

- `recordingId` обов'язковий (не порожній і не лише з пробілів), `duration` обов'язковий і невід'ємний (`>= 0`), `createdAt` обов'язковий у форматі ISO-8601 (`400`).
- `recordingId` унікальний: спроба додати дублікат відхиляється (`409`).
- Під час виправлення `recordingId` незмінний і має збігатися з `{id}` маршруту (`400`).
- Виправлення або видалення неіснуючого запису відхиляється з причиною «об'єкт не знайдено» (`404`).
- Зміни заборонені, якщо оператор недоступний або стан `Call` — `RequestRejected`, `CallFailed`, `QualityEvaluated` чи `SummarySent` (`409`).
