# Контракт HTTP API

Базова адреса: `http://localhost:8080`. Усі відповіді API мають `Content-Type: application/json; charset=utf-8`; повідомлення для користувача — українською. `{id}` у шляху — `recordingId`.

## Запис

```json
{
  "recordingId": "REC-001",
  "duration": 120,
  "createdAt": "2026-11-20T14:30:00"
}
```

`createdAt` — ISO-8601 local date-time без зони/зсуву часу. Сервер виконує всю валідацію; сторінка не відхиляє значення до запиту.

## Маршрути

| Метод і шлях | Призначення | Успішний статус і тіло |
|---|---|---|
| `GET /api/CallCenter` | Повернути всі записи | `200`; JSON-масив об'єктів запису |
| `POST /api/CallCenter` | Додати новий запис | `201`; `{"message":"..."}` |
| `PUT /api/CallCenter/{id}` | Замінити атрибути наявного запису | `200`; `{"message":"..."}` |
| `DELETE /api/CallCenter/{id}` | Видалити запис | `200`; `{"message":"..."}` |

POST і PUT приймають об'єкт запису з розділу «Запис». Для PUT `recordingId` у тілі має дорівнювати `{id}`. Успішна мутація має українське повідомлення; клієнт після неї повторно запитує GET.

## Відмови

Усі відмови мають JSON-тіло `{"message":"українське пояснення"}`.

| Статус | Умова |
|---|---|
| `400 Bad Request` | Некоректний JSON, порожній `recordingId`, від'ємна тривалість, відсутній/некоректний `createdAt` або невідповідність ID тіла і шляху |
| `404 Not Found` | PUT чи DELETE для відсутнього запису |
| `409 Conflict` | Дублікат при POST або зміна, заборонена доступністю оператора/станом дзвінка |
| `500 Internal Server Error` | Помилка сховища; відповідь не містить stack trace чи внутрішньої інформації |

## Статична вебсторінка

- `GET /` віддає `index.html`; `script.js` і `style.css` — із classpath-каталогу `/public`.
- Сторінка показує `recordingId`, `duration`, `createdAt`, має одну форму створення/редагування, показує повідомлення відповіді, підтверджує видалення та перечитує список після кожної успішної зміни.
- Вміст API відображається як текст, не як HTML; відмова й успіх мають різне оформлення; стиль темний і адаптивний.
