# План реалізації: збереження даних кол-центру через SQLite і Guice

**Гілка**: `003-sqlite-guice-persistence` | **Дата**: 2026-11-13 | **Специфікація**: [spec.md](spec.md)

**Вхід**: специфікація функції з `specs/003-sqlite-guice-persistence/spec.md`

## Підсумок

Розширити наявний консольний прототип збереженням об'єктів `CallRecording` із композиції `Call`—`CallRecording` у SQLite та формуванням статичного HTML-звіту. Залишити наявний сценарій і порядок українських повідомлень. Застосувати Maven, JDK 21, Google Guice 7 та sqlite-jdbc; зв'язати інтерфейс сервісу з SQLite-реалізацією, упровадити сервіс у `Call` через конструктор, а екземпляр `Call` отримувати через Guice Injector.

## Технічний контекст

**Мова/версія**: Java, JDK 21  
**Основні залежності**: Maven; Google Guice 7; Xerial sqlite-jdbc; JUnit Jupiter для автоматизованих тестів  
**Зберігання**: файл SQLite `target/callcenter.db`; звіт `target/callcenter-report.html`  
**Тестування**: `mvn test` (JUnit Jupiter), із регресійними перевірками сценаріїв із наявного `CallLifecycleChecks`  
**Платформа**: кросплатформний локальний запуск Java; інструкції для PowerShell/Windows  
**Тип проєкту**: однопроєктний консольний застосунок Maven  
**Цілі продуктивності**: окремі демонстраційні запуски та невелика локальна база; окремих показників продуктивності немає  
**Обмеження**: без зовнішнього сервера; SQL лише в SQLite-сервісі; наявні пакети й бізнес-сценарії зберігаються; помилка запису/читання/звіту має завершувати відповідний запуск без повідомлення про успіх; `target` не очищати між звичайними запусками, бо там міститься база.

## Перевірка відповідності конституції

| Принцип | Перевірка на етапі планування |
|---|---|
| I. Мінімальна складність | Один модуль Maven; один інтерфейс і одна SQLite-реалізація сервісу, модуль Guice та генератор звіту — лише потрібні специфікацією межі. |
| II. Єдина відповідальність | `Call` ініціює збереження; сервіс виконує SQL; генератор формує HTML; модуль налаштовує залежності. |
| III. Імітація зовнішніх операцій | Симуляції телефонії та електронної пошти лишаються незмінними. SQLite і локальний HTML є прямо заданими функціями, а не зовнішніми сервісами. |
| IV. Командний рядок і локальна інфраструктура | Збирання та запуск через Maven; SQLite зберігається у файлі, без сервера БД. |
| V. Інверсія залежностей | `Call` залежить від інтерфейсу сервісу; Guice зв'язує інтерфейс із реалізацією та створює `Call`; залежність передається конструктором. |
| Мовні та SQL-обмеження | Ідентифікатори коду англійською, пояснення й помилки українською; усі SQL-операції локалізовані в сервісі. |

Наведені нові класи є планованими назвами; наявні класи та пакети залишаються у `callcenter`. Модуль Guice зв'язує контекст демонстраційного запуску, щоб створити `Call` через його `@Inject`-конструктор і `injector.getInstance(Call.class)`. `Client` приймає отриманий екземпляр у перевантаженні `requestCallback`; наявні сигнатури й консольна поведінка лишаються сумісними. Тестові класи можуть бути розподілені між наявними й новими перевірками без перейменування предметних класів.

**Рішення щодо структури**: один Maven-модуль зі стандартними `src/main/java`, `src/test/java` і `target`; нові класи додаються до наявного пакета `callcenter`. Публічний інтерфейс функції — команди запуску консолі та їхні файлові результати — описаний у CLI-контракті нижче.

## Фаза 1: модель і контракти

### Модель даних

Єдина сутність для збереження — `CallRecording`, частина `Call` за композицією в `docs/class.mmd`. Ідентифікатор `recordingId` є первинним ключем; повторне збереження цього ключа оновлює атрибути запису. Поля та перевірки наведені в [data-model.md](data-model.md).

### Зовнішній контракт

Застосунок має користувацький інтерфейс командного рядка та файлові результати, тож його команди, передумови, шляхи артефактів і поведінка помилок зафіксовані в [contracts/cli-report.md](contracts/cli-report.md). Сервіс збереження є внутрішнім Java-інтерфейсом, окремий мережевий API не створюється.

### Перевірка запуску

Відтворювані сценарії збірки, тестування, першого запуску та перевірки повторного збереження описані у [quickstart.md](quickstart.md).
