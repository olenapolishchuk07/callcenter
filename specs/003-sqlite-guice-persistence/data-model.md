# Модель даних

## Сутність `CallRecording` (запис розмови)

Це клас-частина, що належить `Call` за композицією `Call *-- "0..1" CallRecording` у `docs/class.mmd`. Один успішно завершений сценарій створює та зберігає його значення; після запуску запис читається зі сховища незалежно від життєвого циклу об'єкта в пам'яті.

| Поле | Тип Java | Тип SQLite | Правило |
|---|---|---|---|
| `recordingId` | `String` | `TEXT PRIMARY KEY` | Обов'язковий унікальний ідентифікатор; повторне збереження цього ключа оновлює решту полів. |
| `duration` | `int` | `INTEGER NOT NULL` | Не може бути від'ємним; відповідає наявній перевірці конструктора `CallRecording`. |
| `createdAt` | `LocalDateTime` | `TEXT NOT NULL` | Зберігається як ISO-8601 local date-time та відновлюється без перетворення часового поясу. |

### Зв'язки

- `Call` має нуль або один `CallRecording`; один запис належить одному `Call` у межах демонстраційного сценарію.
- Сховище не зберігає окремий клас `Call`, клієнтів, операторів, оцінки чи підсумки — специфікація обирає саме композицію із `CallRecording`.
- Сервіс збереження надає предметні операції збереження та отримання списку записів; HTML-звіт не містить власної копії моделі.

### Перевірки та поведінка

- `recordingId` використовується як первинний ключ; UPSERT за цим ключем не створює дубль.
- `duration >= 0`.
- Значення всіх атрибутів, прочитані зі сховища, показуються в окремому рядку HTML-таблиці.
- Текстові значення в HTML екрануються як дані (`&`, `<`, `>`, лапки й апостроф), не змінюючи збережені значення.
- Порожнє сховище дає коректний звіт із заголовками та без рядків даних.
