# Перевірка артефактів UML кол-центру

## Передумови

- PlantUML-сумісний засіб для `docs/usecase.puml`.
- Mermaid-сумісний засіб для `docs/class.mmd`, `docs/sequence.mmd` і `docs/state.mmd`.
- Редактор сумісний із `.xlsx` для `docs/crc.xlsx`.

У межах цієї функції Java-застосунок, база даних і зовнішні сервіси не потрібні. Якщо PlantUML CLI і Mermaid CLI (`mmdc`) вже встановлені, у PowerShell можна виконати приклади нижче; інакше відкрийте файли в редакторах/переглядачах, що підтримують відповідні формати.

## Перевірка джерел і рендерингу

З кореня репозиторію перевірте наявність усіх очікуваних файлів:

```powershell
$expected = @(
  'docs/usecase.puml',
  'docs/class.mmd',
  'docs/sequence.mmd',
  'docs/state.mmd',
  'docs/crc.xlsx'
)
$expected | ForEach-Object {
  if (-not (Test-Path -LiteralPath $_ -PathType Leaf)) {
    throw "Відсутній обов'язковий артефакт: $_"
  }
}
```

За наявності CLI-інструментів відрендерте кожну діаграму до тимчасового каталогу:

```powershell
plantuml -checkonly docs/usecase.puml
plantuml -tsvg -o "$env:TEMP" docs/usecase.puml
mmdc -i docs/class.mmd -o "$env:TEMP/class.svg"
mmdc -i docs/sequence.mmd -o "$env:TEMP/sequence.svg"
mmdc -i docs/state.mmd -o "$env:TEMP/state.svg"
```

Очікуваний результат: PlantUML перевіряє синтаксис, усі чотири джерела діаграм рендеряться без помилок; книга відкривається у XLSX-сумісному редакторі.

## Перевірка узгодженості

1. На use case diagram присутні «Клієнт», «Оператор» і «Супервізор» та всі чотири обов’язкові сценарії.
2. На class diagram перевірте модель, зв’язки, конструктори й операції згідно з [data-model.md](data-model.md), зокрема `final`, перевизначення та перевантаження.
3. Пройдіть sequence diagram від заявки до оцінювання супервізором і успішного надсилання підсумку клієнту; назви учасників та викликів мають узгоджуватися з класами.
4. Переконайтеся, що state diagram показує початковий/кінцевий стани й переходи `NewRequest` → `CallInProgress` → `Recorded` → `QualityEvaluated` → `SummarySent`; невдалі умови не позначені як успішні.
5. Відкрийте всі CRC-картки та зіставте їх із класами діаграми. Кожна картка має назву класу, заголовки «обов'язки класу» і «з ким співпрацює», щонайменше один обов’язок і співробітника або явне зазначення, що співробітників немає.

## Критерій успіху

Перевірка успішна, якщо всі п’ять артефактів відкриваються відповідними засобами, задовольняють свої структурні вимоги та утворюють один узгоджений успішний процес від заявки клієнта до відправленого підсумку.
